## 1. 决策总表

| Q-ID | 问题 | 结论 | 关键依据 | 被否掉的备选 |
|---|---|---|---|---|
| **Q-01** | 免登录能否部署公网 | **平台不实现任何认证**；改为在发布前置检查清单中强制二选一：① 内网/办公网部署 ② 反向代理层提供 SSO 或 IP 白名单 | 维持 P-12「无需登录」；认证属于网络边界职责，做进平台会引入用户体系，与「只有两个角色」直接冲突 | ❌ 平台内加应用级访问令牌 —— 本质是变形登录，违反 P-12 |
| **Q-02** | 甲方是否可见 SQL | **应用级开关 `clientCanViewSql`，默认 false**；开启后甲方只读可见**当前生效** SQL，历史版本仍不可见 | 默认关闭可防表结构外泄；开关满足技术型甲方核对口径的需求 | ❌ 一律不可见（太刚性）；❌ 一律可见（泄露表结构） |
| **Q-03** | 报表是否需要参数 | **一期实现**。`{{name}}` 占位符 + 参数定义（string / number / date / enum）+ **强制参数绑定执行** | 无参数的报表几乎不可复用；参数化同时是防注入最有效的手段，与 REQ-SEC-08 合并落地 | ❌ 一期不做（报表沦为一次性快照）；❌ 二期再补（安全债越拖越大） |
| **Q-04** | 导出格式与上限 | **xlsx + csv**；同步上限 5 万行 / 30 秒，超限自动转异步；文件 TTL **24 小时**，异步任务记录保留 **72 小时** | 80% 场景是小结果，同步体验最好；长尾用异步兜底 | ❌ 加 PDF（报表场景无价值，且大表格排版失真） |
| **Q-05** | 开发者能否代甲方恢复 | **支持，但只恢复到甲方回收站（`RECYCLED`）**，不直接恢复为 `NORMAL` | 甲方对自己视图的处置权应被尊重；开发者只负责"捞回来"，是否放回菜单由甲方决定 | ❌ 直接恢复为 NORMAL（未经甲方确认又出现在菜单，属于越权） |
| **Q-06** | 开发者清空是否需要宽限期 | **默认 7 天，可配置 0 ~ 30 天**；`0` 表示立即物理删除；宽限期内可撤销 | 物理删除不可逆，必须有后悔窗口；可配置兼顾运维效率 | ❌ 固定 7 天不可配（运维无法加速清理）；❌ 无限期保留（记录无限膨胀） |
| **Q-07** | 使用哪家模型 / 是否私有化 | **应用级配置 `llm.endpoint` / `llm.model` / `llm.apiKey`**，默认指向**私有化或经企业合规审批**的接口；出站内容强制为「元数据 + 提示词」并写入出站审计 | A-08「业务数据不出网」是硬约束，优先级高于生成准确率；准确率可用字段注释与多轮修正补偿 | ❌ 固定绑定某家公有云模型（锁定 + 合规风险） |
| **Q-08** | 谁来创建一个「应用」 | **内置平台根应用（`is_platform_root = true`）**，其开发者可创建/停用其他应用；**不引入第三角色** | 治理入口挂在特殊应用上，比新增「平台管理员」角色更贴合 P-09「只有两个角色」 | ❌ 新增 platform_admin 角色（破坏双角色模型）；❌ 只能改配置文件创建（运维负担） |
| **Q-09** | 临时导出是否留痕 | **进审计日志；并新增「我的导出历史」**（当前 clientKey，最近 30 天，支持过期后一键重跑） | 80% 是临时导出，没有历史就得重跑一遍，是体验硬伤 | ❌ 完全不留痕（无法复用、无法审计） |
| **Q-10** | iframe 嵌入的跨域问题 | **提供无边框模式 + postMessage 高度自适应**；**强烈建议宿主用反向代理挂到同域子路径** | 无登录方案依赖 Cookie 保存 clientKey，而第三方 Cookie 正被各浏览器逐步禁用，同域反代是唯一稳妥解 | ❌ 复杂的 postMessage 双向鉴权（把认证复杂度搬进前端） |

## 2. 决策带来的新增约束

### 2.1 发布前置检查清单（Q-01 的落地物，强制项）

部署前必须全部勾选，缺一项不得上线：

| # | 检查项 | 不满足时的后果 |
|---|---|---|
| 1 | 部署于内网/办公网，**或**反向代理已启用 SSO / IP 白名单 | 任何人可访问全部报表 |
| 2 | 所有数据源账号为只读账号，且已验证无写权限 | 平台可被用于篡改业务数据 |
| 3 | 数据源密码已加密存储，接口响应体中已剥离 | 凭据泄露 |
| 4 | SQL 网关五道闸已启用（解析 / 校验 / 改写 / 只读事务 / 脱敏） | 越权查询 |
| 5 | 审计日志已开启，留存 ≥ 180 天 | 无法追溯 |
| 6 | LLM endpoint 已指向私有化或合规审批地址 | 业务数据出网风险 |
| 7 | 导出文件 TTL 与清理任务已生效 | 文件堆积与数据滞留 |

### 2.2 参数模型的边界（Q-03 的落地物）

- 占位符语法：`{{param_name}}`，**只允许出现在 WHERE / HAVING / LIMIT 的值位置**，不允许出现在表名、列名、关键字位置。
- 支持类型：`string` / `number` / `date` / `enum`（单选）。
- `date` 类型提供快捷预设：`最近 7 天` / `最近 30 天` / `本月` / `上月`。
- **参数化是默认执行方式**：即便 SQL 不含占位符，也必须走预编译通道，不允许字符串拼接（REQ-PARAM-07）。
- 参数值不进 SQL 文本 ⇒ 审计日志中记录的是「SQL 模板 + 参数值」两部分，便于事后还原。

### 2.3 应用级配置项清单（`application.settings_json`）

| 键 | 默认值 | 说明 | 来源 |
|---|---|---|---|
| `maxRows` | 50000 | 单次查询行数上限 | Q-04 |
| `timeoutMs` | 30000 | 执行超时 | — |
| `exportFileTtlHours` | 24 | 导出文件 TTL | Q-04 |
| `exportHistoryDays` | 30 | 我的导出历史保留天数 | Q-09 |
| `purgeGraceDays` | 7 | 开发者清空后的物理删除宽限期（0~30） | Q-06 |
| `clientCanViewSql` | false | 甲方是否可见当前生效 SQL | Q-02 |
| `llm.endpoint` / `llm.model` / `llm.apiKeyEnc` | 无 | SQL 生成服务接入配置 | Q-07 |
| `embedMode` | false | 无边框嵌入模式 | Q-10 |
