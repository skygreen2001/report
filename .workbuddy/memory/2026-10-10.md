# 2026-10-10 企业报表平台


## 重做：每数据源各生成一条 SQL + 模型幻觉表名自动修正

**用户反馈**："mftgshop 里也有订单表 mp_user_order，为什么没有找"。

**根因（两层）**：
1. 原方案"多库 prompt 生成一条 SQL，按表名精确匹配候选库"——biz_demo.orders 与 mftgshop.mp_user_order 表名不同，模型只选一个库的表名写 SQL，另一库的相似表无法成候选。
2. 改成"每库并行生成"后，模型对 mftgshop（65 张表，prompt 过长）幻觉表名：把 `mp_user_order` 记成 `mp_core_order`（catalog 无此表）。校验"表必须全在 catalog"直接剔除 → mftgshop 整库无候选 → 用户看不到。

**后端（generation.ts）**：
- generateSql 改为**对每个数据源并行调一次模型**（每库独立元数据，避免跨库表名歧义），返回 `results: [{dataSourceId,name,databaseName,sql,tables}]`；废弃 buildMultiPrompt。
- 校验：SQL 用到的表必须都在该库 catalog；**模型幻觉表名时**，用 catalog 里**共享 token 最多、编辑距离最近**的真实表名自动修正（`mp_core_order` 共享 order→`mp_user_order`，优先于共享 core→`mp_core_juben`），再重校验；修不了才剔除。新增 `levenshtein` / `sharedTokenLen` 辅助函数。
- 清理：移除诊断专用 `console.error` 临时日志；删死代码 `buildMultiPrompt`。

**前端（c/d page.tsx、d/page.tsx）**：候选卡片改用 `results`（每库一条独立 SQL + 表名），选候选项时同步切换 SQL 与数据源；文案改"多个数据库都能满足需求，请选择用哪个库的 SQL"。

**live E2E**：双库同 prompt"各地区的订单数量汇总"→ 连续 2 次稳定返回 2 候选：biz_demo[orders]、mftgshop[mp_user_order,mp_dic_region]，两条 SQL 均合理。tsc 0，网关 20/20。
