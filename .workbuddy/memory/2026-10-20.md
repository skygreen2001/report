# 2026-10-20 企业报表平台

## 报表「全部」分页查看（甲方端）

**需求**：报表详情加「全部」按钮，点击可看 SQL 查询的全部数据（不受预览 200 行限制），并可分页查看。

**实现**：
- 后端 `POST /reports/all`（`api/reports/all/route.ts`，新建）：复用网关五道闸的 Parse→Validate，
  用 `rewriteBase` 移除原 SQL 的 LIMIT（末尾分号一并去掉），包一层派生表：
  先 `SELECT COUNT(*) FROM (base) _c` 拿总数，再 `SELECT * FROM (base) _p LIMIT n OFFSET m` 取当前页
  （LIMIT/OFFSET 为代码生成的整数，安全）。0 行时从 fields 取列名，表头不空白。
  脱敏 applyShape、审计 auditRun（source 记 PREVIEW，不改 run_record ENUM）、限流 30/60s。
  `AllSchema`：page≥1、pageSize 1~200（默认 50）。
- 前端 `c/page.tsx` 报表详情卡：新增 allMode/allPage/allPageSize/allTotal/allLoading 状态与 `loadAll(page, pageSize)`；
  按钮行加「全部」（全部模式下变「退出全部」切回 200 行预览，「刷新数据」变「刷新本页」）；
  表格下出分页条：共 N 行 + 每页 20/50/100/200 下拉 + 上一页/下一页 + 第 X/Y 页。
  runReport/openReport 时退出全部模式（参数变化回到预览）。

**验证**：tsc 0、网关 20/20；接口实测 total=8218 全量、翻页数据不同、page 超范围 0 行、
`{{name}}` 参数绑定正确、原 SQL 自带 LIMIT 3 被移除（total 仍 8218）、0 行列名保留、
DROP TABLE→400、不存在报表→404、pageSize=500→400；
浏览器实测：全部模式 1/165 页 50 行 → 下一页 2/165 首行变化 → 每页 20 行生效 → 退出全部回到「上限 200」预览、分页条消失、无 JS 错误。

## 结果表格列名改用列注释第一行（2026-10-20 上午）

**需求**：列表显示的列名默认使用列的注释第一行，没有注释再使用列名。

**实现**：
- `datasource.ts` 新增 `buildColumnLabels(doc)`：遍历结构文档所有表所有列，`注释.split('\n')[0].trim()` 非空则记入映射；同名列先到先得；空/纯空白注释跳过。
- `preview/route.ts` 与 `all/route.ts`：execute 后 `getSchemaDoc(ds.id)`（有缓存直读、无则现场抓一次并缓存；失败静默回落）构建映射，**只带回结果列中命中的项**（避免整库 ~300 条注释撑大响应），随 `columnLabels` 返回。
- 前端表头 `c/page.tsx`（报表详情）、`d/page.tsx`（新建报表预览 prevCols、需求收件箱 reqCols）：`{labels[c] || c}` 渲染，`title={c}` 保留原始列名供悬停核对。导出（xlsx/csv）表头不变，仍用原始列名。

**验证**：tsc 0、网关 20/20；接口实测 create_time→「下单时间」、openid→「微信用户唯一标示」、表达式/别名列不在映射（回落列名）、响应只含命中列；
单元实测多行注释只取第一行、空白注释跳过、同名列先到先得；
浏览器实测 27 列全部显示注释且 title 为原始列名，全部模式同样生效，无 JS 错误。
