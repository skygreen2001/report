# 2026-10-05 企业报表平台

## 修复：甲方提示「该应用未配置默认数据源」

**现象**：开发者已建数据源，甲方页仍报「该应用未配置默认数据源」。

**根因（两个叠加）**
1. `application.settings_json.defaultDs` 从来没有任何代码路径写入——`createDataSource` 只插 `data_source` 表，不回写应用设置；开发者 UI 也没有「设为默认」入口。`demo` 应用有值只是 seed 手工塞的。
2. 应用缓存失效的 key 对不上：写入用「请求 host」（`127.0.0.1:3111`），失效用库里存的 host（`''` 通配），导致改设置要等 60s TTL 才生效。

**改动**
- `src/server/services/datasource.ts`
  - 新增 `resolveDefaultDataSourceId(ctx)`：settings.defaultDs 为空或已失效时，回落到该应用第一个 `status='ACTIVE'` 的数据源。
  - 新增 `setDefaultDataSource(ctx, id)` + 内部 `writeDefaultDataSource`；`createDataSource` 在该应用尚无默认时自动把新建的设为默认。
- 新增路由 `src/app/tenant/[appPath]/[role]/api/data-sources/[id]/default/route.ts`（POST，仅 DEVELOPER；非开发者 403；不存在 404）。
- `src/server/cache.ts` 新增 `cacheDeleteBySuffix`；`context.ts` 的 `invalidateAppCache` 改为按 `#{pathPrefix}` 后缀全清。
- `bootstrap` 返回的 `settings.defaultDs` 改为「有效值」（回落后的），`preview` / `exports` / `generate` 三处改为 `?? resolveDefaultDataSourceId(ctx)`。
- `GenerateSchema.dataSourceId` 由必填改为可选。
- 开发者页数据源列表加「设为默认」按钮 + 「默认」徽标；甲方页提示改为指出具体应用路径。

**回归**：网关对抗 20/20、live DB 验证 6/6、生命周期 35/35、Web 端到端 15/15（共 76 项全绿）。

**注意（业务约束）**：数据源是按应用隔离的。用户在 `/platform/d` 建的数据源只服务 `/platform/c`；`/bb/c` 没有任何数据源，必须在 `/bb/d` 另建。用户建的 `mftgshop` 两个数据源用的是 `root` 账号，违反平台只读约束，已把 platform 默认切回 `report_ro / biz_demo`。

## 需求：开发者可直接写 SQL 生成报表

**改动**
- `d/page.tsx` 报表 tab 拆成两张卡：「新建报表（直接写 SQL）」+「已有报表」。新建卡含：报表名、数据源下拉（默认取应用默认数据源，另有「（默认数据源）」选项）、SQL 文本域、`{{name}}` 占位符自动识别并生成参数输入框、预览按钮（≤200 行，结果渲染成表格）、保存按钮。
- `SaveReportSchema.dataSourceId` 改可选；`POST /reports` 路由补 `resolveDefaultDataSourceId` 回落。

**顺带修掉两个真实安全缺口（测试时发现）**
1. **保存报表/改 SQL 完全不校验**：`DROP TABLE orders` 能被直接存进 `report` 表，等甲方点开才在网关报错。→ `src/server/sql/gateway.ts` 新增 `validateOnly(sql, databaseName)`（只走 Parse→Validate，不执行、不连业务库、不写运行审计）；`report.ts` 的 `saveReport` 与 `updateSql` 保存前调用。
2. **报表可绑定别的应用的数据源**：`saveReport` 从不校验 `dataSourceId` 归属，应用 A 的报表能指向应用 B 的库。→ 加 `ds.app_id !== ctx.appId → 403 FORBIDDEN`。

**测试脚本相应调整**：`verify-lifecycle.ts` 原来借用 demo 应用的数据源（现在会被 403 拦下），改为给临时应用自建只读数据源；新增 3 条断言（保存 DROP 拒、保存 SLEEP 拒、跨应用数据源拒）；结尾补临时数据自清理。

**回归**：网关 20/20、live DB 6/6、生命周期 38/38、Web 端到端 15/15（共 79 项全绿）。

## 排查：开发者预览返回空/全站 500

**现象**：开发者写了 SQL，连接测试成功，但预览没数据；期间还出现所有接口 500 INTERNAL。

**根因（三个独立问题）**
1. **0 行时连表头都不返回**。`gateway.execute` 用 `shaped[0]` 反推列名，0 行 → `columns: []`，前端一片空白，用户分不清「查到 0 行」和「查询坏了」。→ 改为同时取 mysql2 的 `fields` 元数据，0 行也返回表头。
2. **表/列名写错返回 500 INTERNAL 且泄露 MySQL 原始报文**（`Table 'biz_demo.mp_user_order2' doesn't exist`）。→ `errors.ts` 新增 `mapDbError()`，把 errno 映射成平台码：`1146/1051/1109→TABLE_NOT_FOUND`、`1054→COLUMN_NOT_FOUND`、`1064→SQL_SYNTAX_ERROR`、`1049→DB_NOT_FOUND`、`1044/1045/1142→DB_ACCESS_DENIED`、`3024/1317→QUERY_TIMEOUT`、`1040/1203→DB_BUSY`，统一走 400。同时 `toErrorResponse` 对 SqlReject 改为「开发者看明细、甲方只见编号」。
3. **★ 全站 500 的真凶：MySQL 连接被打满**（`Max_used_connections` 达到 152 > `max_connections` 151）。Next dev 每次热重载都重新执行模块，`platform.ts` 的 `let pool` 和 `datasource.ts` 的 `const pools` 都是模块级变量 → 每改一次代码就新建一个连接池，旧池连接要等 idleTimeout 才释放。这轮连续改了十几次就打满了。→ 两个池子都挂到 `globalThis`（`__platformPool` / `__dsPools`），并加 `idleTimeout: 30_000`；熔断状态 `broken/brokenUntil` 也一起挂 globalThis。实测：连续 8 次热重载后 `Threads_connected` 稳定在 6（修复前会持续上涨）。

**前端**：开发者页新建报表卡显示「当前数据源：xxx · 库名」；预览 0 行时给出黄色提示 + 三条排查建议（字段存的是编码不是中文、时间范围、选错数据源）。

**verify.ts 新增 ⑦⑧**：0 行仍返回表头；表/列名写错 → TABLE_NOT_FOUND / COLUMN_NOT_FOUND。

**回归**：网关 20/20、live DB 8/8、生命周期 38/38、Web 端到端 15/15×2（连跑两遍均通过，连接数稳定在 7）。

## 修复：保存报表报「paramsSchemaJson: Expected string, received null」

**根因**：`SaveReportSchema.paramsSchemaJson` 是 `z.string().optional()`，只接受「字符串或不传」；而 `d/page.tsx` 在没有 `{{param}}` 占位符时显式传了 `null` → zod 报 `Expected string, received null`，被 `toErrorResponse` 映射成 400 VALIDATION_ERROR 弹在页面上。

**改动**
- `src/server/schemas.ts`：所有可选字符串字段统一改 `.nullish()`（`SaveReportSchema` 的 dataSourceId/paramsSchemaJson/parentNodeId、`PreviewSchema`/`ExportSchema`/`GenerateSchema` 的 reportId/sql/dataSourceId/currentSql、`CreateDsSchema.sensitive_columns_json`、`CreateAppSchema.host`、`UpdateSqlSchema.note`、`RequirementSchema` 全部）。以后前端传 null 不再炸。
- 下游类型收口（否则 tsc 报 `string|null` 不能赋给 `string|undefined`）：`preview`/`exports` 路由 `?? undefined`；`sql` 路由 `body.note ?? undefined`；`applications` 路由 `host: body.host ?? ''`；`generate` 路由显式构造 `GenerateInput`。
- `src/server/errors.ts` 新增 `humanizeZodMessage()`：zod 英文提示转中文（null→「不能为 null（不传该字段，或传字符串）」、Required→「必填」、too_small→「内容太短」、regex→「格式不合法…」等）。
- `d/page.tsx`：无占位符时干脆不带 `paramsSchemaJson` 字段（服务端已兼容 null，双保险）。

**验证（live，dev 3111）**：`paramsSchemaJson:null` → 201；省略该字段 → 201；带参数占位符 `SELECT 1 AS n FROM DUAL WHERE 1 = {{p}}` + paramsSchemaJson 字符串 → 201；`name:""` → 400「name: 内容太短，不满足最小长度」；`sqlText:null` → 400「sqlText: 不能为 null（不传该字段，或传字符串）」。三条测试报表已清理（先走 `/reports/{id}/delete` 进回收站，再 SQL 删 placement/sql_version/report）。
