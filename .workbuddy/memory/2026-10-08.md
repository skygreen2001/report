# 2026-10-08 企业报表平台


## 新增：开发者端回收站 UI

**现状核查**：后端回收站本就是双轨——`report` 表 `client_state`/`developer_state` 两列；`lifecycle.deleteReport/restoreReport` 按 `ctx.role` 走对应 track；`tagTree.RECYCLE_BIN` 每角色一棵树；`listReports` 已返回 `developer_state` 与 `tag_node_id`。开发者端只缺前端 UI（d/page.tsx 原有报表只有 chips 列表，无删除/回收站）。

**改动（d/page.tsx）**：
- 加 `delReport(id)`（confirm 后 POST `/reports/{id}/delete`，role=d 自动 developer track）、`restoreRep(id)`（POST `/reports/{id}/restore`）。
- 组件内 `inDevBin = r.developer_state==='RECYCLED'`、`normalReports`/`binReports` 过滤（用 developer_state，不依赖 tagTree）。
- 报表卡片改写：正常报表每行带「删除」，下方「回收站（n）」区列 binReports 带「还原」。
- 侧边导航加「回收站（n）」入口（同 c 端 setTab('reports')）。

**E2E（live）**：对开发者端 NORMAL 报表调 /delete→developer_state=RECYCLED；bootstrap(role=d) 回收站含该报表；/restore→NORMAL。数据已还原。tsc 0 错误。


## 调整：回收站与报表彻底分开（开发者 + 甲方两端）

**需求**：开发者端回收站和报表要分开；甲方报表里不能看到回收站里的内容。

**改动（c/page.tsx、d/page.tsx）**：
- 两端 `tab` 字面量联合均加 `'bin'`，回收站从「报表卡片内嵌区」改为**独立 tab 视图** `{tab === 'bin' && ...}`。
- 报表列表只渲染 `normalReports`（非回收项），回收站内容只出现在独立「回收站」页。
- 导航「回收站（n）」入口改 `setTab('bin')` 并按 `tab === 'bin'` 高亮（c 端 `node bin` 样式）。
- 开发者端判断用 `developer_state==='RECYCLED'`；甲方端用 `nodeOf(tag_node_id)?.kind_uniq==='RECYCLE_BIN' || client_state==='RECYCLED'`（既有逻辑，未改）。

**live E2E（demo 应用「各地区订单汇总」）**：开发者 delete → 开发者报表不含/回收站含；甲方「我的报表」仍含（双轨隔离，开发者删除不影响甲方）、甲方回收站不含、甲方报表无回收项混入；restore → 回开发者报表。数据已还原干净。tsc 0 错误。

**E2E 踩坑（重要）**：
1. 报表「剧本」`client_state` 本就是 RECYCLED（甲方自己删过，本就在甲方回收站）——E2E 写断言前必须先查清报表既有状态，否则误判为 bug。
2. 对多个 application 循环调 delete 会误改非目标应用数据：report 属别的 app 时返回 `404 REPORT_NOT_FOUND`（非鉴权问题）。E2E 要锁定单个 app 的 path_prefix。
3. 本次 debug 脚本误把「剧本」`developer_state` 删成 RECYCLED，已用 `/restore` 还原为 NORMAL；`client_state=RECYCLED`（用户既有）保持不动。


## 修正：回收站提示文案（各角色各自独立的回收站）

用户指出回收站提示「仅甲方侧不可见」表述错误——正确语义是**每个角色各有自己的回收站、互不干扰**（双轨：甲方删只影响甲方可见，开发者删只影响开发者可见）。

改动（纯文案）：
- `c/page.tsx` 回收站 pill：`仅甲方侧不可见` → `甲方自己的回收站 · 与开发者互不干扰`；删除提示 → `已移入甲方回收站（开发者侧不受影响）`。
- `d/page.tsx` 回收站 pill：`开发者侧草稿 · 甲方不可见` → `开发者自己的回收站 · 与甲方互不干扰`；confirm → `确认移入开发者回收站？开发者与甲方各有各的回收站，本操作只影响开发者侧，甲方仍可见。`
- 未动 `d` 端 `甲方已不可见` 徽标（那是甲方 PURGED 状态，语义正确，REQ-LIFE-08）。tsc 0 错误。


## 功能：SQL 生成跨所有数据源 + 多库同名表让用户选库

**需求**：生成新报表的 SQL 应基于所有开发者已连接的数据库；多个库有类似表时让用户选择用哪个 SQL/库生成报表。

**后端（generation.ts）**：
- `GenerateInput` 加 `dataSourceIds?: string[]`（`dataSourceId` 保留兼容）；`GenerateResult` 加 `dataSourceId` / `candidates[{id,name,databaseName}]` / `ambiguous`。
- 新增 `resolveTargets`：显式多源 > 单个 > 本应用全部 ACTIVE 数据源；只取 `status='ACTIVE'`；**补了归属校验** `ds.app_id !== ctx.appId → 403`（原来 `loadDataSource(input.dataSourceId)` 完全没校验归属，是越权缺口）。
- 新增 `buildMultiPrompt`（多源时每个库的表结构分块标注「数据源名 · 库名」）、`extractTables`（正则提取 FROM/JOIN 后的表名）。
- 生成后用 `extractTables` 匹配哪些库的 catalog 含这些表：只匹配 1 个 → 直接定 `dataSourceId`；匹配多个 → `candidates` + `ambiguous:true`。
- schemas `GenerateSchema` 加 `dataSourceIds`；generate 路由透传。

**前端**：c 端 `gen()` 传全部 `dsList` id，新增 `genDsId`/`genCandidates`，多候选时渲染选库卡片，preview/save/export 改用 `effDsId = genDsId || dsId`；d 端 `genFromReq()` 同样传全部 id，新增 `reqCandidates`，选库即 `setReqDsId`。

**坑**：c 端 `dsList` 类型是 `DsLite`（无 `status` 字段）→ 前端不能 filter status，改由后端统一只取 ACTIVE。

**live E2E**：① 单源 → dataSourceId 直接定；② 双源（biz_demo + mftgshop）→ understanding 明确「已根据 2 个数据源的元数据生成」，只 biz_demo 命中 → 单库定；③ 复制出一个 host 不同的同源库制造「两库都有 orders」→ `ambiguous=true` + candidates 2 条（含名称与库名），临时数据源已删除、无残留。tsc 0 错误。
