## 功能：生成 SQL 进度条 + 取消生成 + 切菜单不丢失

**需求**：生成 SQL 时右侧显示加载进度条 + 取消按钮，用户可切其他菜单，回来仍显示进度/结果。

**改动（c/page.tsx、d/page.tsx）**：
- 引入独立生成态 `genLoading/genCancelled/genStage` + `useRef<AbortController>`（c 端）；d 端对应 `reqGenLoading/reqCancelled/reqStage/reqAbortRef`，不再用全局 busy 阻塞生成按钮。
- globals.css 加 `.gen-loading/.gen-spinner/.gen-progress/.gen-stage` + `@keyframes gen-indeterminate / gen-spin`（Apple 风 indeterminate 进度条动画）。
- gen()/genFromReq()：请求前 `setGenLoading(true)` + 阶段文案循环（读表结构→生成 SQL→校验），`fetch` 带 `signal: ctrl.signal`；成功清 cancelled，catch `AbortError` 标 cancelled，finally 清 loading+定时器；d 端 dataSources 统一传全部 id（后端只取 ACTIVE，修正了之前 DsLite 无 status 的 filter 隐患）。
- cancelGen()/cancelReqGen()：`abort()` 中断 fetch，立即显示「已取消」+ 重新生成按钮。
- 渲染：加载中在右侧结果区显示进度条 + 取消按钮 + 「可切菜单，回来显示结果」提示；已取消显示重试；候选/结果卡片用 `!loading && !cancelled` 包裹。
- 关键：这些 state 都是组件顶层 hook，切 tab 是 `{tab===...}` 条件渲染而非卸载组件 → 切走再切回仍保留进度/结果（天然满足需求，无需额外持久化）。

**验证**：tsc 0；dev(3111) 编译 /platform/c 与 /platform/d 均 200。
**说明**：取消是前端 AbortController 中断（立即停止等待、丢弃结果、可离开）；后端模型调用无法中途停，会在服务端跑完但前端不再阻塞。若要「后端也真正停」，需改流式 SSE + 取消端点，后续可加。

## 功能：「停止生成」按钮 —— 真正中断模型调用（省算力）

**需求**：在「仅取消等待」之外再加一个停止按钮，真正停掉后端模型调用。

**后端（generation.ts）**：
- 新增任务注册表（挂 `globalThis` 防 HMR 丢失）：`registerGenTask/unregisterGenTask/stopGenTask`，任务含 `{ctrl, appId, role}`；`stopGenTask` 校验**同 appId + 同 role** 才 abort（防跨租户/跨角色误停）。
- `generateSql` 拆为 wrapper + `generateSqlInner(ctx, input, signal)`：wrapper 建 AbortController（有 taskId 则注册），并把 `req.signal`（客户端断开）也绑到同一 ctrl；`finally` 清理注册与监听。
- **模型调用透传中断**：`client.chat.completions.create(params, { signal })` → abort 后到模型的 HTTP 请求立即断开，模型停止推理（本地 ollama 同样生效）。
- 每个库的 task：发起模型调用前先查 `signal.aborted` 早退（不再发新调用）；`results` 判定前若已 aborted 则返回 `{mode:'manual', stopped:true, reason:'生成已被用户停止'}`（不再误降级成"生成失败"），并写 `GEN_STOP` 审计。
- schemas：`GenerateSchema` 加 `taskId`；新增 `StopGenerateSchema`。
- 新路由 `POST /[role]/api/reports/generate/cancel`（`reports/generate/cancel/route.ts`）：调 `stopGenTask`，返回 `{stopped}`。

**前端（c/page.tsx、d/page.tsx）**：
- 生成时创建 `taskId`（`crypto.randomUUID`）随请求带上；新增 `stopGen`/`stopReqGen`：先 POST cancel 端点中断后端模型调用，再 abort 前端 fetch。
- 进度条下**两个**按钮：「停止生成」（danger，真正中断）+「仅取消等待」（ghost，只停本页等待）；新增 `stopped` 态区分提示（"已停止，模型调用已中断" vs "已停止本页等待，模型仍会跑完"）；候选/结果卡片加 `!stopped` 条件。

**live 验证**：
1. baseline 完整生成 26039ms / 2 条候选 → 证明 `req.signal` 不会误触发中断。
2. 发起后 951ms 调 cancel → `{stopped:true}`，原请求 **955ms** 即返回（vs 完整 26s），省掉 25s 模型推理 → **证明真的中断了模型调用**。
3. 安全隔离：开发者停甲方任务 → `stopped:false`；不存在 taskId → false 且不报错；甲方停自己 → true。
tsc 0、网关 20/20。

**经验**：`req.signal` 绑进生成是 bonus（关页面/abort 也自动省算力），但必须靠 baseline 正常生成来确认它不会在正常请求上误触发。
