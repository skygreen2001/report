
## 修复导出 csv/xlsx 报 JSON 解析错误（2026-10-19）

**现象**：导出 csv 报 `Unexpected non-whitespace character after JSON at position 4`；导出 xlsx 报 `Unexpected token 'P', "PK"... is not valid JSON`。

**根因**：`GET /exports/{id}` 是「状态查询 + 文件下载」二合一接口——任务 RUNNING 时返回 JSON 状态，DONE 时**直接返回文件二进制**。前端 `pollExport` 每秒轮询都无条件 `r.json()`，导出完成那一刻拿到 xlsx（`PK` 文件头）/ csv 文本去解析 JSON 就抛 SyntaxError；且轮询无 try/catch，变成 Uncaught promise。

**修复**（`c/page.tsx`）：
- `pollExport` 先判 `content-type`：非 JSON → 任务已完成，直接用 `r.blob()` 建对象 URL + `<a download>` 触发下载（从 Content-Disposition 取文件名），不再二次 fetch、也不再用 `window.open`（规避弹窗拦截）。
- JSON 分支处理 FAILED / DONE-无文件（提示重新导出）；加 try/catch，网络抖动连续失败 10 次才终止并提示。
- `doExport`/`exportReport` 的 POST 响应解析改为 `r.json().catch(() => ({}))`（项目约定），错误响应非 JSON 时也不再抛 SyntaxError。

**验证**：tsc 0、网关 20/20；Node 模拟修复后轮询逻辑实测：RUNNING×3 → 拿到 xlsx（magic=504b 即 PK，1.8MB）/ csv（3.4MB）均正确走文件分支，无 JSON 解析错误。

## 修复「导出不断重复下载」（2026-10-19 下午）

**现象**：上一轮修完 JSON 解析错误后，用户反馈「点击导出 csv 发现不断的导出文件」。

**排查**（Playwright + 系统 Chrome 实测复现）：
- 干净单击：1 POST + 1 下载，正常。
- **重复点击即重复导出**：导出完成后按钮立刻恢复可点，再点就再建任务再下载（实测 2 次）。
- **busy 被复位漏洞**：`openReport` 对无参数报表会自动 `runReport`，其 `finally { setBusy(false) }` 会在导出进行中把共享 `busy` 复位、解除导出按钮禁用——导出途中点「查看」其他报表即可让按钮中途可点。
- **setInterval+async 叠代风险**：单次轮询（大文件）超 1s 时，在飞行中的回调完成 clearInterval 后仍会执行下载。

**修复**（`c/page.tsx`）：
- 新增导出专用状态 `exportBusy` + 进行中标志 `exportInFlight`（useRef）：导出全程（建任务→轮询→下载）独立锁定，与查询/预览的 `busy` 彻底隔离；handler 入口再挡一次重复点击。
- `pollExport` 改为返回 Promise + `settled` 终态标志：整个轮询最多触发一次下载，免疫叠代；加 5 分钟兜底上限；网络抖动连续失败 10 次才终止。
- 4 个导出按钮 `disabled={busy || exportBusy}`，导出中按钮文案变「导出中…」，开始导出时 msg 提示「正在导出，请稍候…」。

**验证**（浏览器实测）：单击=1POST+1下载；导出中途点「查看」其他报表后导出按钮仍禁用（修复核心）；完成后可正常再导出。tsc 0、网关 20/20。
