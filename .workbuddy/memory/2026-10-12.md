# 2026-10-12 企业报表平台

## ⚠ 架构修订（第二段）：扁平化「人」模型 —— 已取代上午的 OWNER 版

上午先按「1 甲方(OWNER)+多外部开发者」实现，用户推翻重做。最终模型（已落地、tsc0、网关20/20、live 验证通过）：

**核心理念**：人人平等，没有特殊甲方。每个使用者 = 一个平等的工作区（workspace）。
- 身份仅靠 URL 里的 `ws` key（免登录、capability URL）。
- `/d`（不带 ws）→ 应用**默认工作区**（第一个 DEVELOPER 行，名「主开发者」）—— 原单开发者体验、可共用。
- `/d?ws=<key>` → 该使用者自己的私密空间；未知但合法的 18 位 hex key **开放预建**空工作区；非法 key → 404。
- `/c` → 甲方视图，聚合**所有**工作区产出的报表（人人可见，按 ws_name 标注来源）。
- 角色(d/c)与身份(ws)正交：同一个人既是开发者也是甲方，看从哪个入口进。

**代码落点**：
- 删 `ensureOwnerWorkspace`、`listWorkspaces`/`createDevWorkspace`/`renameWorkspace`/`rotateWorkspaceKey`/`setWorkspaceStatus`/`assertOwner`；`devWorkspace.ts` 仅留 `getDefaultWorkspace`/`ensureDefaultWorkspace`/`resolveWorkspace`。
- `context.ts`：`RoleContext` 去掉 `wsKind/wsName`，只留 `wsId`；`wsKey=readWsKey()` 可为 null → `resolveWorkspace(appId, wsKey)`。
- `middleware.ts`：d 和 c 都从 `?ws` 参数或 `wsKey` Cookie 取身份（不再只为 d 设）。
- `llm.ts`：模型按 `ws_id + scope(=ctx.role)` 隔离（/d 配 DEVELOPER，/c 配 CLIENT，各私密）；`scope` 取 `ctx.role`。
- `application.ts`：建应用时只建 1 个默认工作区。
- UI：删「开发者协作」tab、顶栏「工作区：xx」徽标，菜单还原原样（数据源/文档/需求/报表/模型配置/应用管理/回收站）。
- 迁移 `scripts/migrate-ws-flatten.ts`：把早期 OWNER 工作区配置并回默认工作区、删 OWNER 行、所有 `llm_provider.ws_id` 指向默认。

**验证（live 3111）**：plain /d 见存量(业务只读库+1报表)；新 key 自动开空私密空间(0/0)；/c 汇总 1 条带 ws_name；非法 key→404。

## （已废弃）上午初版：OWNER 层级模型

~~目标：1 甲方(OWNER)+多外部开发者，甲方特殊、可管理席位。用户确认不要此结构（不要特殊甲方、不要席位管理 UI、菜单还原）。以下仅留痕，勿沿用。~~
- 初版曾加 `dev_workspace.kind ENUM('OWNER','DEVELOPER')`、开发者协作 tab、workspace 徽标、席位管理 API。均已回退。

- 甲方有自己那份 OWNER 开发者配置，切到 /d 看不到任何外部开发者的东西。
- 甲方 /c 汇总所有工作区产出的报表。

### 数据模型

- 新表 `dev_workspace(id, app_id, ws_key UNIQUE, name, kind ENUM('OWNER','DEVELOPER'), status)`。
- `data_source` / `report` / `tag_node` / `llm_provider` 各加 `ws_id` 列 + `idx_app_ws`。
- `tag_node.uk_system_node` 改为 `(app_id, role, kind_uniq, ws_id)`、`idx_parent` 含 ws_id
  → 开发者侧**每个工作区各一棵树**（ROOT + 回收站）。
- 迁移脚本 `scripts/migrate-dev-workspace.ts`（幂等）：
  存量配置归入自动创建的「主开发者」工作区；每应用补一个 kind=OWNER 的「甲方（我自己的配置）」。
  甲方侧 `llm_provider`（scope=CLIENT）归 OWNER，开发者侧归主开发者。

### 身份解析

- `middleware.ts`：`/d?ws=<key>` → 写 `wsKey` Cookie + `x-ws` 头。
- `context.ts`：role=c → `ensureOwnerWorkspace`；role=d → `resolveWorkspace(appId, wsKey)`，
  **无 ws 参数即 OWNER**（甲方自己的），ws 无效/停用直接 404，**绝不回落别人的工作区**。
- `RoleContext` 新增 `wsId / wsKind / wsName`；`bootstrap` 回传 `workspace`。

### 服务作用域

- `datasource.listDataSources(ctx)`：DEVELOPER 按 `ws_id` 过滤；CLIENT 全应用（汇总）。
- `report.listReports(ctx)`：DEVELOPER 限自己 ws；CLIENT 全应用并 LEFT JOIN 出 `ws_name`。
- `llm.listProviders`：按 ws + scope；甲方 OWNER 的模型在 /c 与自己的 /d 共用。
- `generation.resolveTargets`：走 `listDataSources(ctx)`，自动继承上述作用域。
- `devWorkspace.ts`：开席位（生成 18 位随机 ws_key + `initDevTree`）、改名、轮换密钥、停用；
  `assertOwner` 只允许 OWNER 工作区管理（`listWorkspaces` 对外部开发者返 403）。

### API / UI

- `api/dev-workspaces`（GET/POST）、`[id]`（PATCH 改名/启停）、`[id]/rotate`（POST）。
- d 页顶栏显示「工作区：xxx」；OWNER 才显示「开发者协作」tab（开席位 / 复制邀请链接 / 轮换 / 停用）。
- c 页报表行加「来自：<工作区名>」徽标，甲方知道报表出自哪个开发者。

### 验证（live，端口 3111）

- 甲方 /d → OWNER，数据源 0（存量在主开发者）；主开发者 /d?ws= → 数据源 1、报表 1；
  新开「李四」→ 数据源 0、报表 0（互相隔离 ✓）。
- 李四调 `/dev-workspaces` → 403 FORBIDDEN；停用后其链接 → 404 WORKSPACE_NOT_FOUND。
- 甲方 /c 汇总到 1 条报表并带 `ws_name=主开发者`。
- tsc 0 错误；网关对抗 20/20；/demo/d、/demo/c、/demo/d?ws=… 均 200。
