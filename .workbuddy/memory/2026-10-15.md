# 2026-10-15 企业报表平台

## 开发者菜单新增「甲方可见 SQL」开关（应用级）

**需求**：开发者菜单里加一个开关，控制甲方能否在报表详情看到 SQL。

**实现**：数据模型早就有 `settings_json.clientCanViewSql`（默认 false），`GET /reports/{id}`
也已按它裁掉 `currentSql`（历史版本恒定不可见）。缺的是「保存接口 + UI 开关」。本次补齐：
- `application.ts` 新增 `updateAppSettings(appId, patch)`：读行→合并已知字段→写回
  `settings_json`→`invalidateAppCache` 即时失效（否则甲方要等 60s TTL）。
- 新增路由 `api/settings` `PUT`：仅 DEVELOPER（甲方不可改，否则被一键关掉自己却看不到）；
  只认 `clientCanViewSql` 布尔，其余字段忽略。
- 开发者页 `d/page.tsx`：内容区顶部常驻一张开关卡片（`<label class="switch">` + 说明 +
  `已开启/已关闭` 徽标），`load()` 从 `boot.settings.clientCanViewSql` 取初值；
  `globals.css` 加 `.switch`/`.slider`/`.pill.ok` 样式。

**验证**：tsc 0；PUT 返回 ok 并即时生效；甲方 `GET /reports/{id}` 的 `currentSql` 随开关
true→可见 / false→不可见（实测 true→false 立即翻转）。`/platform/d` 200。
⚠ 注意：`scripts/seed.mjs` 给 platform 应用 seed 的是 `clientCanViewSql:true`，
故该应用默认甲方可见 SQL，属种子数据，非 bug。

## 开关只放「数据源」tab + 关时甲方也不看结构文档

**需求演变**：① 开关原本常驻内容区顶部（全 tab 可见）→ 改为只在开发者「数据源」tab 顶部显示；
② 当 `clientCanViewSql=false` 时，甲方连「数据库结构文档」也不显示（SQL 与结构文档同属「暴露库表结构」）。

**改动**：
- `d/page.tsx`：把开关卡片从常驻区移入 `tab === 'ds'` 的 `<>...</>}` 片段顶部（不再全页常驻）。
- `[role]/api/data-sources/[id]/schema/route.ts`：`GET` 增加接口层拦截——
  `CLIENT && !clientCanViewSql` 抛 `403 CLIENT_SCHEMA_HIDDEN`；开发者恒可见。
- `c/page.tsx`：①「数据库结构文档」导航节点与 tab 内容加 `settings?.clientCanViewSql` 条件；
  ② `?tab=doc` 深链也受同一开关约束（关时即便深链也不跳到 doc）。

**验证**：tsc 0；网关 20/20；实测 schema 接口 关→甲方 403 / 开发者 200，开→甲方 200；`/platform/d`、`/platform/c` 均 200。

## 甲方不可见 SQL 时「生成」按钮文案改为「生成报表」

**需求**：`clientCanViewSql=false` 时，甲方「生成新报表」tab 的主按钮文字用「生成报表」而非「生成 SQL」。

**改动**：`c/page.tsx` 增加 `const genLabel = settings?.clientCanViewSql ? '生成 SQL' : '生成报表';`，
用于 ① 主按钮 ②「正在{genLabel}」加载态 ③ 两处提示里指代按钮名的「生成 SQL」。
开发者侧（可见 SQL）仍显示「生成 SQL」。

**验证**：tsc 0；`/platform/c` 200。

**背景**：用户问「`dev_workspace.ws_key` 在哪里，我找不到」。它不在代码里，是 MySQL 表
`report_platform.dev_workspace` 的一列，界面上看不到（上一轮按「界面不要动」的要求撤掉了徽标）。

**改动**：
- 新增常驻脚本 `scripts/ws-list.ts`（幂等只读）：列出全部工作区的 应用 / 名称 / 状态 / claimed /
  数据源数 / 报表数 / **ws_key**，并直接打印换设备用的 `/{app}/d?ws=<key>` 链接。
  运行：`env -u NODE_OPTIONS .../node node_modules/tsx/dist/cli.mjs scripts/ws-list.ts`
- `bootstrap` 接口回传 `workspace.wsKey`（只回给本人）：浏览器地址栏直接打开
  `/{app}/d/api/bootstrap` 就能看到自己的身份 key，无需连库、无需改 UI。
  → `types.ts` `RoleContext` 加 `wsKey`；`context.ts` 赋值 `wsKey: ws.ws_key`；
  → 三个 verify/smoke 脚本的 `RoleContext` 字面量同步补 `wsKey: ws.ws_key`。
- 修正 bootstrap 里一处过期注释（还写着 OWNER 层级）。

**三种查 key 的方式（给用户）**：
1. 浏览器打开 `http://127.0.0.1:3111/demo/d/api/bootstrap` → JSON 里 `workspace.wsKey`
2. `node_modules/tsx/dist/cli.mjs scripts/ws-list.ts`
3. `mysql -u root -proot report_platform -e "SELECT ws_key,name,claimed FROM dev_workspace;"`

**⚠ 运维要点（沿用 10-13 结论，本次再次踩到）**：
- 「第一个调用 `/api/*` 的浏览器」会认领该应用 `claimed=0` 的工作区，并把 ws_key **替换成自己的随机串**。
  因此联调后必须复位：`UPDATE dev_workspace SET claimed=0 WHERE app_id=...`，并删掉测试产生的新工作区
  （连同 `tag_node WHERE ws_id=...`）。
- 本次测试后已复位：demo / platform / bb 三个「主开发者」均为 `claimed=0`；
  同时清掉了一个测试遗留的空工作区，以及一个 app 早已不存在的孤儿工作区 `86b18a2c`。
- demo 工作区当前 ws_key = `641159fb284844059f`（待认领，用户浏览器接管后会再变）。

**验证**：tsc 0 错误；网关对抗 20/20；`/demo/d`、`/demo/c` 均 200；
两 cookie jar 实测：浏览器1 认领存量（数据源1/报表1，wsKey=641159fb284844059f），
浏览器2 拿到全新空空间（数据源0/报表0）。

## 应用管理：应用「添加 / 删除」功能（2026-10-15 下午）

**需求**：开发者页「应用管理」tab 已有「添加」（创建应用，早就通了），缺口是「删除」。本次补齐删除全链路，
并顺手硬化「添加」的重复路径校验、统一应用管理操作的开发者角色校验。

**改动**：
- `application.ts`：
  - 新增 `deleteApplication(ctx, id)`：仅 `DEVELOPER` + `is_platform_root` 可调用；
    平台根不可删（`CANNOT_DELETE_ROOT`）；不存在 404；
    用 `platformTx` 事务**级联删**全部子表（无 FK 约束，显式按 app_id 清）：
    `report_placement`（按 report 归属）→ `run_record`/`sql_version`/`export_task`/`requirement`/`audit_log`
    → `report`/`data_source`/`llm_provider`/`tag_node`/`dev_workspace` → `application`；最后 `invalidateAppCache`。
  - `createApplication` 增加 `uk_host_path` 重复校验 → 409 `PATH_PREFIX_DUPLICATE`（避免重复 path_prefix 触发 500）。
  - `disableApplication`/`enableApplication` 同步加 `ctx.role!=='DEVELOPER' → 403 REQUIRES_DEVELOPER`
    （与删除一致，堵住客户端经 `/{app}/c/api/applications/...` 越权管理应用的口子）。
- 新增路由 `api/applications/[id]/route.ts` `DELETE`：`withRole` + `deleteApplication`。
- `d/page.tsx`「应用管理」tab：
  - 非平台根应用每行加「删除」按钮（红色），停用/启用合并为一个切换按钮；
  - 新增 `deleteApp(a)`：强确认弹窗（提示数据永久不可恢复）→ `DELETE` → `load()` 刷新；
  - `createApp` 把重复路径错误映射成中文「路径前缀已存在，请换一个」，创建成功后清空表单。

**验证**：tsc 0；网关 20/20。`/platform/d` 200。
实测：开发者 POST 建 `dt` → 列表出现 → 插 1 数据源+1 报表（创建时已自动建 4 tag_node+1 dev_workspace）
→ DELETE 200 → 12 张子表计数全 0、列表不再含 `dt`；
边界：重复 path_prefix 409 / 删平台根 400 / 删不存在 404 / **客户端角色 DELETE 403**、开发者 200。

**运维**：本次 3111 实例已死（另有个 3000 在跑），已用 `env -u NODE_OPTIONS .../node node_modules/next/dist/bin/next dev -p 3111` 重启。
注意「应用管理」tab 仅 `boot.app.isPlatformRoot` 时显示——即只有平台根应用（path_prefix=platform）的开发者能看到。
