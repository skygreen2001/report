### 本轮修复的真实缺陷
1. **information_schema 列名大小写**：MySQL 返回 `TABLE_NAME`/`COLUMN_NAME` 大写，代码按 `t.table_name` 取值为 undefined → 全部加 `AS` 别名（`src/server/services/datasource.ts`、`src/server/db/datasource.ts`）。
2. **末尾分号被判多语句**：LLM 输出 `SELECT ...;` 被 node-sql-parser 拆成 2 条 → `parser.ts` 只剥离尾部分号，内部 `;` 仍按 MULTI_STATEMENT 拒绝。
3. **restoreReport 取错表**：`origin_parent_id` 在 `report_placement` 上，代码从 `report` 上读 → 静默回落根目录。已改为从 placement 读。
4. **hardDelete 删文件顺序错**：先 DELETE export_task 再查 file_key，永远查不到 → 改为先取清单再删行，提交后删文件。
5. **导出 INSERT 占位符缺失**：`export_task` 10 列只有 9 个 `?`（缺 format）→ 补齐。
6. **rewrite 后角色丢失**：middleware rewrite 成 `/tenant/...`，`resolveContext` 按 `/{app}/{c|d}` 解析错位 → middleware 用 `x-app-path`/`x-role` 请求头传递，context 保留路径兜底。
7. **应用匹配**：库里 `host=''` 而请求 host 是 `127.0.0.1:3111` → 改为「精确 host 优先 OR host=''」匹配。
8. **zod 校验错误被吞成 500**：`toErrorResponse` 增加 ZodError → 400 VALIDATION_ERROR；`withRole` 拆两段 try，开发者可见错误明细。
9. **preview/export 的 sql 必填**：改为 reportId / sql 二选一。
10. **generation.ts 死代码**（buildPrompt 返回字符串赋给未用变量）已清理。

### 沙箱环境坑（重要，后续复用）
- `npm install` 被网络代理中断，node_modules 里大量包**只有目录、缺文件**（package.json 为空、缺 dist/lib）。
- 解法：`curl https://registry.npmjs.org/<pkg>/-/<pkg>-<ver>.tgz` 直取 tarball + `tar -xzf ... --strip-components=1` 覆盖。注意用 tar 直接解，BSD `cp -R` 会产生嵌套目录。
- 自动升级到 latest 会造成大版本不兼容（fast-csv 5 vs 4、compress-commons 7 vs 4、crc32-stream 7 vs 4、bl 7 vs 4、nanoid 6 vs 3）→ 必须按宿主包声明的 semver 范围**显式锁版本**。
- `readable-stream` v3 无根目录 `passthrough.js`，lazystream/archiver-utils/duplexer2 需要 v2 → 在各自目录下嵌套装 2.3.8。
- 缺少 tsx/esbuild 时，用 `node node_modules/typescript/bin/tsc -p <tsconfig>` 编译到 `.verify-build` 再 node 运行；`@/` 别名在 CJS 产物里不生效，需 `node -r ./scripts/alias.cjs` 注入解析钩子。
